# 五项核心原则评分标准 (Five Core Principles Rubric)

本 rubric 明确评估每个 Reviewer 对五项核心原则的遵守程度。

## 评分权重

| 原则 | 权重 | 说明 |
|------|------|------|
| P1: Goal Mode | 20% | 只检查结果，不检查过程 |
| P2: Execution Gate | 25% | 必须有真实证据 |
| P3: Adversarial | 25% | 禁止自我验证 |
| P4: Persistence | 15% | 持久化交接 |
| P5: Right-Size | 15% | 规模匹配 |

## P1: Goal Mode Constraint (20分)

### 定义
只描述最终状态，不写实现步骤。Reviewer 检查结果是否对齐目标，不检查过程。

### 评分标准

| 分数 | 描述 | 证据要求 |
|------|------|----------|
| 20 | 完全符合 | 评分基于目标达成，不引用实现细节 |
| 16-19 | 基本符合 | 评分主要基于目标达成，有少量实现引用但不影响判断 |
| 12-15 | 部分偏离 | 评分包含实现过程检查，偏离了"只看结果"原则 |
| 8-11 | 严重偏离 | 评分主要基于实现细节，而非目标达成 |
| 0-7 | 完全偏离 | 没有任何基于目标的评分 |

### 检测问题
```
❌ "代码按照步骤实现了 X" - 过程描述
❌ "使用了 Y 设计模式" - 实现细节
❌ "参考了 Z 文件的写法" - 过程引用
✅ "功能 X 返回了正确的 {a: string} 格式" - 结果描述
✅ "API /goals 返回了符合 schema 的 Goal 对象" - 结果验证
```

### 扣分项
- 引用实现步骤作为评分依据: -5
- 要求按特定方式实现而非验证结果: -10
- 检查代码风格而非功能正确性: -5

---

## P2: Execution Gate (25分)

### 定义
每个 reviewer 必须提供可验证的证据。禁止"代码看起来正确"作为评分依据。

### 评分标准

| 分数 | 描述 | 证据要求 |
|------|------|----------|
| 25 | 完全符合 | 所有评分都有 L1-L3 级别证据支撑 |
| 21-24 | 优秀 | 95% 评分有可验证证据 |
| 17-20 | 良好 | 80% 评分有可验证证据 |
| 13-16 | 及格 | 60% 评分有可验证证据 |
| 8-12 | 不足 | <60% 有可验证证据 |
| 0-7 | 严重不足 | 几乎没有可验证证据 |

### 证据层级（按可信度）

| 层级 | 证据类型 | 可信度 |
|------|----------|--------|
| L1 | 自动化测试通过 | ⭐⭐⭐⭐⭐ |
| L2 | 构建成功 | ⭐⭐⭐⭐ |
| L3 | 类型检查通过 | ⭐⭐⭐ |
| L4 | 静态分析通过 | ⭐⭐ |
| L5 | 代码审查（主观） | ⭐ |

### 扣分项
- 没有测试输出却声称测试通过: -10
- 没有构建输出却声称构建成功: -5
- 使用"看起来正确"等主观描述: -3
- 证据没有具体文件:行号: -2

---

## P3: Adversarial Review (25分)

### 定义
Reviewer 必须独立运行，不能依赖执行者的自我总结。禁止引用自己刚写的代码。

### 评分标准

| 分数 | 描述 | 证据要求 |
|------|------|----------|
| 25 | 完全符合 | 所有证据来自历史文件，无自我引用 |
| 21-24 | 优秀 | 有 1-2 处轻微违规但不影响判断 |
| 17-20 | 良好 | 有少量自我引用但有其他证据支撑 |
| 13-16 | 及格 | 有较多自我引用，证据可信度下降 |
| 8-12 | 不足 | 主要依赖自我引用 |
| 0-7 | 严重不足 | 几乎完全是自我验证 |

### 证据来源规则

| 来源 | 可接受 | 示例 |
|------|--------|------|
| 历史文件 | ✅ | `apps/.../existing-file.ts:45` |
| 已有测试 | ✅ | `pnpm test` 输出 |
| 其他 Reviewer 报告 | ✅ | `round-001/xxx/score.md` |
| 新增代码 | ❌ | `git diff` 中新增的内容 |
| 执行者声称 | ❌ | "我测试了，这个功能正常" |

### 检测问题
```
❌ 引用 git diff 中新增的代码作为证据
❌ "我们添加了这个测试" - 自我引用
❌ "按照上面的实现" - 引用刚写的代码
✅ 引用项目历史文件中的现有代码
✅ 引用 `pnpm test` 的实际输出
```

### 扣分项
- 引用 diff 中新增代码: -10
- 引用"上面的代码"或"刚才的实现": -5
- 没有引用任何外部证据: -15

---

## P4: Persistent Handoff (15分)

### 定义
每个 phase 的计划和结果必须写入文件，支持回溯和问题定位。

### 评分标准

| 分数 | 描述 | 证据要求 |
|------|------|----------|
| 15 | 完全符合 | 所有必需文件存在且格式正确 |
| 13-14 | 优秀 | 所有文件存在，有 1-2 处格式问题 |
| 10-12 | 良好 | 缺少 1-2 个非关键文件 |
| 7-9 | 及格 | 缺少 3-4 个文件 |
| 4-6 | 不足 | 缺少大部分文件 |
| 0-3 | 严重不足 | 几乎没有交接文件 |

### 必须生成的文件

```
round-XXX/
├── metadata.json          # ✅ 评审元数据（自动生成）
├── summary.md             # ✅ 汇总报告（自动生成）
├── phase-N-plan.md        # ✅ N 轮计划（自动生成）
├── phase-N-result.md      # ✅ N 轮结果（自动生成）
└── <reviewer>/
    ├── result.yaml         # ✅ 机器可读结果
    ├── score.md            # ✅ 评分详情 + 证据
    ├── blockers.md         # ✅ P0/P1 问题
    └── improvement-list.md # ✅ P2/P3 建议
```

### 扣分项
- 缺少 result.yaml: -3
- 缺少 score.md: -3
- 缺少 blockers.md: -2
- 缺少 improvement-list.md: -2
- 缺少 summary.md: -2
- 缺少 metadata.json: -2
- 文件格式不正确: -1/文件

---

## P5: Right-Size Throttle (15分)

### 定义
根据变更规模自动调整评审复杂度。小改动不搞仪式，大改动强制流程。

### 评分标准

| 分数 | 描述 | 证据要求 |
|------|------|----------|
| 15 | 完全符合 | 评审深度与规模精确匹配 |
| 13-14 | 优秀 | 深度匹配，有轻微偏差 |
| 10-12 | 良好 | 基本匹配，有 1-2 处偏差 |
| 7-9 | 及格 | 有明显不匹配 |
| 4-6 | 不足 | 规模与深度严重不匹配 |
| 0-3 | 严重不足 | 完全不匹配 |

### 规模与评审深度映射

| 规模 | 文件数 | 行数 | 评审深度 | 自动化检查 |
|------|--------|------|----------|------------|
| Micro | ≤2 | ≤100 | 快速 | git diff |
| Small | ≤5 | ≤500 | 标准 | git diff + lint |
| Medium | ≤20 | ≤2000 | 完整 | git diff + test + typecheck |
| Large | ≤50 | ≤5000 | 深度 | git diff + test + typecheck + audit |
| XLarge | >50 | >5000 | 全面 | 所有 + 架构评审 |

### 评审深度不足的判定

| 场景 | 期望 | 实际 | 判定 |
|------|------|------|------|
| XLarge 变更 | 全维度评审 | 只有 quick review | ❌ 深度不足 |
| Micro 变更 | 快速检查 | 全维度评审 | ⚠️ 过度评审 |
| Large + 安全变更 | 安全专项评审 | 没有 data-security reviewer | ❌ 缺少必要评审 |

### 扣分项
- XLarge 变更但没有架构评审: -5
- Large 变更但跳过 test/typecheck: -3
- Medium 变更但没有 conditional reviewer: -2
- 过度评审（Micro 做了 full review）: -2（效率问题）

---

## 综合评分计算

```
总原则得分 = P1*0.2 + P2*0.25 + P3*0.25 + P4*0.15 + P5*0.15

评审员原则合规性评分 = round(总原则得分)
```

### 评级

| 评级 | 分数 | 说明 |
|------|------|------|
| ⭐⭐⭐⭐⭐ | 95-100 | 卓越，完全遵守五项原则 |
| ⭐⭐⭐⭐ | 85-94 | 优秀，有轻微偏差 |
| ⭐⭐⭐ | 75-84 | 良好，有改进空间 |
| ⭐⭐ | 60-74 | 及格，需要显著改进 |
| ⭐ | <60 | 不及格，严重偏离原则 |
